# C++ TCP 멀티플레이 게임 서버

> 3학년 네트워크 게임 프로그래밍 팀 프로젝트

TCP/IP 소켓 프로그래밍을 기반으로 2인 파티 플레이를 지원하는
멀티플레이 게임 서버를 구현한 프로젝트입니다.

클라이언트 접속 및 플레이어 상태 동기화, 패킷 기반 통신,
멀티스레드 환경의 공유 데이터 보호와 파티 플레이 중재를 구현했습니다.

## 주요 구현 내용

- TCP/IP Socket 기반 Client-Server 통신
- 패킷 헤더 기반 가변 길이 패킷 처리
- 클라이언트별 Recv Thread 구성
- 플레이어 접속 및 상태 동기화
- 이동 / 애니메이션 / 스킬 동기화
- Mutex를 이용한 공유 플레이어 데이터 보호
- 서버 중재 방식의 2인 파티 플레이

## 1. Client-Server 구조

[시스템 구조 이미지]

클라이언트와 서버는 별도의 `RecvThread`에서 패킷을 수신하고,
패킷 타입에 따라 플레이어 상태를 갱신하도록 구현했습니다.

클라이언트의 Main Loop에서는 게임 Update / Render를 처리하고,
서버에서는 접속한 클라이언트의 상태를 관리하고 다른 클라이언트에
필요한 정보를 전달합니다.

## 2. 패킷 처리

패킷 타입과 크기를 포함하는 고정 길이 헤더를 먼저 수신한 뒤,
헤더에 기록된 크기만큼 실제 패킷 데이터를 수신하도록 구현했습니다.

이를 통해 플레이어 정보, 이동, 장면 전환, 스킬 생성,
파티 상태 등 서로 다른 크기의 패킷을 처리했습니다.

## 3. 플레이어 상태 동기화

새로운 플레이어가 접속하면 서버의 플레이어 컨테이너에 정보를
등록하고, 신규 플레이어와 기존 플레이어가 서로의 초기 상태를
전달받도록 구현했습니다.

이후 이동, 애니메이션, 스킬 등의 상태 변경을 서버를 통해
상대 클라이언트에 전달했습니다.

## 4. 멀티스레드 동시성 제어

서버는 클라이언트별 `RecvThread`를 사용하므로 여러 스레드가
공유 플레이어 컨테이너에 동시에 접근할 수 있습니다.

플레이어 접속 및 이동으로 공유 데이터가 변경되는 구간을
Mutex로 보호하여 Data Race를 방지했습니다.

## 5. 2인 파티 플레이

서버에서 두 플레이어의 파티 준비 상태를 관리했습니다.

클라이언트가 파티 상태 변경을 요청하면 서버에서 상태를 갱신하고
상대 플레이어에게 변경 사항을 전달합니다.

두 플레이어가 모두 Ready 상태가 되면 파티 플레이를
진행하도록 구현했습니다.
